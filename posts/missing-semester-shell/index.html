1. 提示符与基本形态

missing:~$ date
Fri 10 Jan 2020 11:49:31 AM EST
  • missing：主机名
  • ~：当前工作目录，~ 是 home 目录的简写（Linux 上通常是 /home/用户名）
  • $：普通用户；root 用户通常显示 #
  • 输入一行命令后回车，Shell 解析并执行，然后等待下一条

命令的解析规则：按空白（空格、Tab）拆分整行，第一个词是要执行的程序，其余每个词作为参数传给它。

echo hello        # echo 打印参数
date              # 打印当前日期时间

2. 导航

命令 作用
cd 路径 切换当前工作目录（Shell 内建命令，which cd 找不到文件）
pwd 打印当前工作目录
echo $PWD 同上，读取环境变量 $PWD
ls 路径 列出目录内容 
cd /bin        # 绝对路径
cd bin         # 相对路径（相对当前目录）
cd ~           # 回到 home
cd ..          # 上一级目录

绝对路径 vs 相对路径

  • 绝对路径：以 / 开头，从根目录写完整路径
  • 相对路径：不以 / 开头，相对当前工作目录解析
  • 特殊路径：. 当前目录，.. 父目录

效率技巧

  • 按 Tab 自动补全路径
  • zoxide 提供的 z 命令：记住常访问目录，快速跳转

ls -l 与文件权限

ls -l 每行输出 7 个字段，其中第一个字段是权限位：

-rwxr-xr-x  1  user  group  1234  Jan  1 10:00  run.sh
↑↑↑ ↑↑↑ ↑↑↑
│   │   └── 其他用户：r-x
│   └────── 所属组：r-x
└────────── 文件类型 + 所有者：rwx
  • 第一个字符： - 普通文件，d 目录，l 符号链接
  • r 读（4）、w 写（2）、x 执行（1），三组分别是所有者 / 所属组 / 其他用户
  • 对目录而言，x 表示能进入该目录，r 表示能列出内容
  • 权限也可用数字表示：rwxr-xr-x = 755，rw-r--r-- = 644
chmod +x run.sh      # 给脚本加执行权限，才能 ./run.sh 运行
chmod 755 run.sh     # 数字写法，等价于 rwxr-xr-x

这是讲义里「Shell 会在 $PATH 中找到同名文件，前提是该文件可执行」的那一环：脚本写好后必须 chmod +x。

3. 参数里的空格：引号与转义

参数本身含空格或特殊字符时（例如目录 My Photos）：

"My Photos"     # 双引号括起来
'My Photos'     # 单引号括起来
My\ Photos      # 反斜杠转义空格

三种写法的区别不只是风格，关键在于变量是否展开：

写法 变量 $name 典型用途
"My $name" 展开为变量的值 大多数情况首选，保留空格又允许替换
'My $name' 不展开，原样输出字面文本 正则、含大量特殊字符的字符串
My\ $name 只转义紧跟着的一个字符 单个空格或特殊字符
$'a\nb' ANSI-C 转义，\n 变成真换行 需要换行、制表符等控制字符时 
name=alice
echo "hello $name"    # hello alice
echo 'hello $name'    # hello $name
echo "文件存在"       # 中文和空格在双引号里都安全

注意：[ "$var" = "string" ] 里的双引号不能省，否则变量为空时 [ 会看到参数个数不对而报错。

4. 查手册

命令 说明
man date 查看命令完整手册
date --help 简短帮助信息
tldr date 常用示例（需安装 tldr）

在 man 的翻页界面里：

按键 作用
空格 / f 下一页
b 上一页
/关键词 向下搜索（按 n 跳到下一个匹配）
q 退出

man 内容很长，但它是离线可用的权威文档；--help 通常更快，tldr 直接给例子。

5. 程序从哪来：$PATH

Shell 执行命令时，会在 $PATH 列出的目录（以 : 分隔）里逐个查找同名可执行文件。

echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

which echo       # 查看命令实际对应的文件，如 /bin/echo
/bin/echo $PATH  # 绕过 $PATH，用完整路径直接执行
ls /bin          # 列出 $PATH 里某个目录的全部程序

which cd 找不到结果，是因为 cd 是 Shell 内建命令，不是磁盘上的可执行文件。

6. 文本查看与简单处理

命令 作用
cat hello.txt 打印整个文件
sort hello.txt 按字典序排序后输出
uniq hello.txt 去掉连续重复行
head hello.txt 打印前几行
tail hello.txt 打印后几行（tail -n 20 指定行数）
grep pattern hello.txt 输出匹配 pattern 的行

常用选项（后面拆解 SSH 管道时会用到）：

sort -n file              # 按数值排序（不是字典序，10 不会排在 2 前面）
sort -nk1,1 file          # 按第 1 列数值排序；k1,1 表示只用第 1 列
uniq -c file              # 每行前面加上出现次数
tail -n 10 file           # 最后 10 行
paste -sd, file           # 把所有行用逗号拼成一行（-s 串行合并，-d, 指定分隔符）
grep -r -n pattern .      # 递归搜索当前目录，并显示行号

注意 uniq 只去掉相邻的重复行，所以常见写法是先 sort 再 uniq：

sort file | uniq -c | sort -nk1,1     # 统计词频并按次数升序排列

pattern 是正则表达式，可表达复杂匹配规则。grep 不指定文件时默认从标准输入读取，配合 -r 时可以指定目录递归搜索。

7. 查找文件：find

# 下载目录里超过 30 天的 zip 文件
find ~/Downloads -type f -name "*.zip" -mtime +30

# home 目录里大于 100M 的文件并列出详情
find ~ -type f -size +100M -exec ls -lh {} \;

# 当前目录下所有包含 TODO 的 .py 文件
find . -name "*.py" -exec grep -l "TODO" {} \;

要点：

  • -type f 只找普通文件
  • -name "*.zip" 按名字匹配（加引号防止 shell 先展开）
  • -mtime +30 修改时间超过 30 天；-size +100M 大小超过 100M
  • -exec 命令 {} \;：对每个匹配文件执行命令，{} 是文件路径占位符，\; 表示命令结束（分号要转义）

与 xargs 配合：处理空格文件名

-exec 是「每个文件执行一次命令」。如果命令支持一次接收多个文件，用 xargs 通常更高效，但必须处理文件名里的空格：

find . -type f -name '*.sh' -print0 | xargs -0 wc -l
  • -print0 让 find 用 NUL 字符（\0）而不是换行分隔文件名
  • xargs -0 按 NUL 拆分参数
  • NUL 不可能出现在文件名里，所以空格、Tab、换行都不会把文件名拆错

-print0 和 -0 必须成对使用：只改一边，文件名里的空格仍会被拆开。

8. sed：流式编辑

sed -i 's/pattern/replacement/g' hello.txt

把文件里所有 pattern 替换为 replacement：

  • -i：直接修改文件（否则只输出到终端）
  • s/：substitute，替换
  • 两个 / 分隔「匹配模式」和「替换内容」
  • /g：global，每行替换所有匹配（不加只替换每行第一个）

pattern 也支持正则，replacement 可以用 \1 等引用捕获组。

-E：扩展正则表达式

sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' log.txt
  • -E 启用扩展正则：( )、+、?、| 等元字符不需要反斜杠转义
  • 不使用 -E 时，基本正则里要写成 \(.*\)、\+
  • (.*) 是捕获组，匹配到的内容可用 \1 在替换部分引用

SSH 管道里那条 sed -E 就是靠捕获组把用户名从日志行里抠出来的。

9. awk：按列解析

awk '{print $2}' hello.csv        # 打印每行第二列（默认按空白分列）
awk -F, '{print $2}' hello.csv    # 指定逗号分隔，再打印第二列

awk 用来「解析」结构化文本（如 CSV），除了取列，还能过滤行、求和、统计。

10. 管道 |

把前一个程序的标准输出，接到后一个程序的标准输入。

cmd1 | cmd2 | cmd3

之所以可行，是因为多数命令行程序在未给出 file 参数时，会从标准输入读取数据。管道是 Shell 组合（compose）程序的核心机制。

标准流：每个程序启动时有三条默认的输入输出通道。

编号 名称 默认指向
0 stdin（标准输入） 键盘
1 stdout（标准输出） 终端屏幕
2 stderr（标准错误） 终端屏幕

关键点：管道 | 只接 stdout，stderr 仍然直接显示在终端上，不会传给下一个命令。

经典组合：SSH 日志管道

ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
  | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \
  | sort | uniq -c \
  | sort -nk1,1 | tail -n10 \
  | awk '{print $2}' | paste -sd,
# postgres,mysql,oracle,dell,ubuntu,inspur,test,admin,user,root

逐段拆解：

片段 作用
ssh myserver 'journalctl ... \| grep "Disconnected from"' 在远程机器上取本次启动的 sshd 日志，筛出断开连接的行
sed -E 's/... (.*) .../\1/' 用扩展正则的捕获组，把整行替换成用户名
sort \| uniq -c 先排序让相同名字相邻，再统计每个名字出现次数
sort -nk1,1 \| tail -n10 按第 1 列（次数）数值排序，取出现最多的 10 个
awk '{print $2}' 只保留第 2 列，也就是用户名
paste -sd, 把 10 行拼接成一行，用逗号隔开

注意 uniq 只去相邻重复，所以 sort 必须在 uniq 之前；sort -nk1,1 必须指定按数值排，否则 10 会排在 2 前面。

11. 重定向与 tee

写法 作用
> file 标准输出写入 file（覆盖）
>> file 标准输出追加到 file
< file 从 file 读取输入（而非键盘）
2> file 标准错误写入 file
2>&1 把 stderr 指向当前 stdout 指向的地方，常配合 > all.log 2>&1
tee 同时输出到屏幕和文件 
verbose cmd | tee verbose.log | grep CRITICAL

完整日志存进 verbose.log，终端只显示筛出来的关键行。

2>&1 的顺序陷阱

这两条命令不一样：

cmd > all.log 2>&1     # 正确：stdout 和 stderr 都进 all.log
cmd 2>&1 > all.log     # 错误：stderr 指向"当时的 stdout"（屏幕），stdout 进 all.log

原因：2>&1 的含义是「把 fd 2 指向 fd 1 当前指向的地方」，它是按顺序执行的。

  • 第一种：先把 fd 1 改到文件，再让 fd 2 跟着 fd 1 → 都进文件
  • 第二种：先让 fd 2 跟着 fd 1（此时 fd 1 还是屏幕），再把 fd 1 改到文件 → 错误继续显示在屏幕，只有正常输出进文件

记住写法：2>&1 放在重定向的后面。

12. 条件判断

if command1; then
    command2
    command3
fi

也可以加 else。command1 常用 test 命令（简写为 [）：

[ -f file ]            # 文件是否存在
[ "$var" = "string" ]  # 字符串是否相等
[[ -f file ]]          # bash 更安全的内置形式，引号处理更少坑

注意：[、] 两侧必须有空格。

13. 循环、命令替换与退出状态

while：只要条件成功就不断重复

while command1; do
    command2
done

for：遍历列表

for varname in a b c d; do
    command
done

命令替换 $()：先执行命令，用其输出替换整个 $()

for i in $(seq 1 10); do
    echo $i
done

老式写法是反引号 `seq 1 10`，但应优先用 $()，因为它支持嵌套。

退出状态 $? 与 &&、||

每条命令结束时都有一个退出状态：成功是 0，失败是非 0。$? 保存上一条命令的退出状态。

grep foo file.txt
echo $?            # 0 表示找到了，1 表示没找到

&& 和 || 根据退出状态决定是否执行后面的命令（短路运算）：

mkdir -p dir && echo "创建成功"     # 前面成功（0）才执行后面
[ ! -d dir ] && mkdir dir          # 目录不存在才创建
cmd || echo "cmd 失败了"            # 前面失败（非 0）才执行后面

这就是脚本里「失败即退出」（set -e）和 flaky test 循环「成功就继续重试」的底层机制。

常用特殊参数：$1 是第一个脚本参数，$@ 是全部参数，$? 是上一条命令退出状态，$! 是上一个后台进程的 PID，$$ 是当前 Shell 的 PID。"$@" 的引号不能省，否则每个参数里的空格会被拆开。

14. 写脚本

推荐把脚本写进 .sh 文件。示例（反复运行测试直到失败，同时后台压 CPU，用于复现 flaky test）：

#!/bin/bash
set -euo pipefail

# 后台启动 CPU 压力
stress --cpu 8 &
STRESS_PID=$!

# 日志文件
LOGFILE="test_runs_$(date +%s).log"
echo "Logging to $LOGFILE"

# 反复运行测试直到失败
RUN=1
while cargo test my_test > "$LOGFILE" 2>&1; do
    echo "Run $RUN passed"
    ((RUN++))
done

# 清理并报告
kill $STRESS_PID
echo "Test failed on run $RUN"
echo "Last 20 lines of output:"
tail -n 20 "$LOGFILE"
echo "Full log: $LOGFILE"

关键点

  • #!/bin/bash：shebang（解释器指示行），执行时把脚本内容交给 /bin/bash
  • set -euo pipefail：严格模式
    • -e 任一命令失败立即退出
    • -u 使用未定义变量直接报错
    • -o pipefail 管道中任一程序失败即算整个管道失败
  • &：后台运行命令
  • $!：上一个后台进程的 PID
  • ((RUN++))：算术扩展
  • > "$LOGFILE" 2>&1：stdout 和 stderr 都写进日志

调试：set -x

set -x    # 开启跟踪：每条命令执行前打印展开后的形式，带 + 前缀
set +x    # 关闭跟踪

调试变量展开、引号、参数拆分问题时特别有用——你能直接看到 Shell 实际执行的那条命令。也可以只包住可疑的几行：

set -x
echo "hello $name"
set +x

函数

bash 和 Python 一样有函数，用来把重复的逻辑收起来：

greet() {
    echo "Hello, $1"
}

greet alice          # Hello, alice
greet "Tom Smith"    # Hello, Tom Smith

函数内部用 $1、$2 取调用时传入的参数，$@ 是全部参数。

运行脚本

写好之后需要执行权限：

chmod +x script.sh    # 否则 ./script.sh 会报 Permission denied
./script.sh           # . 表示当前目录，不能省略
bash script.sh        # 这种调用方式不需要 +x

15. 推荐的现代替代工具

传统命令 替代 好处
ls eza 更现代友好
cat bat 语法高亮、分页
grep ripgrep (rg) 默认递归、更快

写脚本时建议用 shellcheck 静态检查，能揪出大量 bash 陷阱。当脚本膨胀到 100 行以上，也可以考虑改用 Python 等更正式的语言。

16. 常见坑速记

  • 参数含空格：用引号或 \ 转义；"..."，会展开变量，'...' 不会
  • [ 和 ] 两侧必须有空格；[ "$var" = "x" ] 里的引号不能省
  • > 覆盖、>> 追加，别搞混
  • 2>&1 的顺序有讲究，要写在 > 之后
  • uniq 只去相邻重复，先 sort 再 uniq
  • sort -n 按数值排，不然 10 排在 2 前面
  • find -name 的模式要加引号，防止被 shell 提前展开
  • find ... -print0 必须配 xargs -0，否则空格文件名会被拆开
  • sed 用捕获组时记得 -E，不然括号要写 \(
  • 优先用 $() 而非反引号
  • 脚本开头写 #!/bin/bash，第二行写 set -euo pipefail
  • 调试时 set -x 看展开后的命令，退出状态用 $? 查
  • 脚本要 chmod +x 才能用 ./script.sh 运行
  • bash 坑很多，写完跑 shellcheck

17. 附录：curl 与 jq

课程讲义正文没展开这两个工具，但习题里会用到。

curl：从 URL 取数据

curl https://example.com/page.html      # 输出网页内容到终端
curl -s https://example.com/data        # -s 静默模式，不显示进度条
curl -L -o page.html https://example.com  # -L 跟随重定向，-o 保存到文件

jq：处理 JSON

echo '{"name":"alice","age":30}' | jq -r .name
# alice
  • jq 读取 JSON 输入，按过滤器提取或转换数据
  • -r（--raw-output）输出纯字符串，而不是带引号的 JSON 字符串
  • 常用于 curl ... | jq ... 组合：下载接口数据后直接提取需要的字段
curl -s https://api.example.com/users | jq -r '.items[] | .name'

19. 题目解析

1. 确认当前 Shell 是否合适

在终端中运行以下命令查看默认登录 Shell：

echo $SHELL

如果输出 /bin/bash、/usr/bin/zsh 或类似类 Unix Shell 路径即说明符合要求。

  • 补充验证：$SHELL 显示的是用户的默认登录 Shell；如果想确认当前正在运行的 Shell 进程，可运行 echo $0 或 ps -p $$。
  • Windows 用户：不能直接使用 cmd.exe 或 PowerShell，需安装 WSL（Windows Subsystem for Linux） 或 Linux 虚拟机并在其中打开 Bash/ZSH。

2. ls -l 的作用及前 10 个字符含义

ls -l 以长列表格式（long listing format）显示目录内容，包含文件类型、权限、硬链接数、所有者、所属组、大小、修改时间和文件名。

运行 ls -l / 后，每行最前面 10 个字符的含义如下：

  • 第 1 个字符（文件类型）：- 普通文件、d 目录、l 符号链接；其他常见类型：c（字符设备）、b（块设备）、p（命名管道）、s（套接字）
  • 第 2～4 个字符（所有者权限 / User）：依次为读 r、写 w、执行 x（- 表示无该权限）
  • 第 5～7 个字符（所属用户组权限 / Group）：依次为 r、w、x
  • 第 8～10 个字符（其他用户权限 / Others）：依次为 r、w、x

注：在部分系统文件（如 /tmp 或 /usr/bin/sudo）中，执行位 x 的位置可能会看到 s/S（SUID/SGID）或 t/T（Sticky Bit）。

3. 什么是 glob？及模式匹配实验

glob（源自早期 Unix 的 /etc/glob 程序）在 Shell 中指路径名扩展 / 文件名通配符匹配（Pathname Expansion）——即 Shell 根据通配符模式，自动将其展开为当前路径下所有匹配的文件名列表。常见通配符包括：

  • *：匹配任意数量（包括 0 个）的任意字符（不包含以 . 开头的隐藏文件首字符）
  • ?：匹配单个任意字符
  • [...]：匹配括号内的任意单个字符（如 [abc]、[0-9]）

注意区别：

  1. 在 find ~/Downloads -type f -name "*.zip" -mtime +30 中，*.zip 被双引号括起来是为了防止 Shell 提前展开，而是把通配模式原样传给 find 内部进行匹配。
  2. {a,b,c}.txt 严格来说属于花括号扩展（Brace Expansion）而非 glob：无论对应文件是否存在，Shell 都会先把它展开成 a.txt b.txt c.txt。

实验命令：

mkdir -p /tmp/glob_test && cd /tmp/glob_test
touch a.txt b.txt c.txt file1.txt file2.txt file10.txt

ls *.txt         # 匹配所有 .txt 文件
ls file?.txt     # 匹配 file1.txt、file2.txt（不匹配 file10.txt）
ls {a,b,c}.txt   # 展开为 ls a.txt b.txt c.txt 并列出这几个文件

4. 三种引号的区别 & 输出包含 $、! 和换行符的字符串

  • '单引号'（强引用）：保留内部所有字符的字面值，不做任何变量替换、命令替换、历史扩展或转义解析（内部不能直接包含单引号本身）。
  • "双引号"（弱引用）：保留大部分字符的字面值（如空格、*、~ 均不展开），但仍会解析：
    • $（变量替换、命令替换 $(...)、算术扩展 $((...))）
    • `（反引号命令替换）
    • \（仅在后接 $、`、"、\ 或换行符时作为转义）
    • !（在交互式 Bash 中触发历史记录扩展）
  • $'ANSI 引号'（ANSI-C Quoting）：整体按单引号处理（不展开 $ 变量、不触发 ! 历史扩展），但会解析 C 语言风格的反斜杠转义序列（如 \n 换行、\t 制表符、\\ 反斜杠、\' 单引号等）。

输出同时包含字面量 $、! 和换行符的命令：

# 使用 $'...'（推荐，利用 ANSI-C 引号特性）：
printf '%s' $'$!\n'
# 或者在中间包含换行符，效果更直观：
echo $'$\n!'
# 也可以直接用 printf：
printf '$!\n'

5. 标准流与重定向

运行 ls /nonexistent /tmp 时，/tmp 的内容会输出到 stdout（1），/nonexistent 的报错会输出到 stderr（2）。

  1. 分别重定向到两个文件：

    ls /nonexistent /tmp > out.txt 2> err.txt

    （> 等价于 1>）

  2. 将 stdout 和 stderr 都重定向到同一个文件：

    # 通用 POSIX 写法（注意顺序：先重定向 stdout，再让 stderr 指向 stdout）：
ls /nonexistent /tmp > all.txt 2>&1

# Bash 简写：
ls /nonexistent /tmp &> all.txt

    ⚠️ 注意顺序：2>&1 > all.txt 是错误的——它会先把 stderr 指向原来的终端，再把 stdout 重定向到文件，导致报错依然打印在屏幕上。

6. 一行命令：仅当 /tmp/mydir 不存在时创建它

[ -d /tmp/mydir ] || mkdir /tmp/mydir

或者使用 &&：

[ ! -d /tmp/mydir ] && mkdir /tmp/mydir

（若想防止 /tmp/mydir 恰好是一个已存在的普通文件，也可用 [ ! -e /tmp/mydir ] && mkdir /tmp/mydir。）

7. 为什么 cd 必须是 Shell 内建命令，而不能是独立程序？

当 Shell 执行一个外部独立程序（例如 /bin/ls）时，操作系统会通过 fork 创建一个子进程来运行它。在 Unix/Linux 进程模型中，每个进程都有自己独立的“当前工作目录（CWD）”和环境状态：

  • 子进程只能修改自己的工作目录，无法反向修改父进程（即当前 Shell）的工作目录。
  • 如果 cd 是一个独立程序，它只在自己的子进程里切换了目录，程序退出后，父进程 Shell 的当前目录依然停留在原地，没有任何效果。

因此，cd 必须由 Shell 进程自己作为内建命令（builtin）来执行，直接调用操作系统的 chdir() 系统调用修改当前 Shell 进程自身的工作目录。

8. 编写检查文件是否存在的脚本

#!/bin/bash

if [ -z "$1" ]; then
    echo "用法: $0 <文件名>"
    exit 1
fi

if [ -f "$1" ]; then
    echo "文件 '$1' 存在（且是一个普通文件）。"
else
    echo "文件 '$1' 不存在（或不是普通文件）。"
fi

（注：[ 和 ] 前后必须有空格；"$1" 加双引号可以防止文件名含空格或为空时出错。）

9. ./check.sh somefile 报错与 chmod +x 的必要性

  1. 直接运行 ./check.sh somefile 会报错：

    -bash: ./check.sh: Permission denied

  2. 执行 chmod +x check.sh 后再运行：脚本能够正常执行并输出判断结果。

  3. 为什么这一步是必须的：

    • 在 chmod +x 之前，ls -l check.sh 的权限通常为 -rw-r--r--，缺少可执行权限位 x。当你直接用 ./check.sh 方式要求操作系统内核启动该文件时，内核会检查权限位，没有 x 就会拒绝执行并报 Permission denied。
    • 执行 chmod +x check.sh 后，权限变为 -rwxr-xr-x（增加了 x 位），内核才允许直接执行它，并读取首行的 shebang #!/bin/bash 来启动 Bash 运行脚本内容。

10. set -x 的作用

在脚本中加入 set -x（或以 bash -x script.sh 运行）会开启 Bash 的执行跟踪（xtrace）调试模式。它会在每条命令实际执行前，将经过变量替换、通配符展开、命令替换后的最终完整命令打印到标准错误（stderr），并在行首加上 $PS4 的值（默认为 +）。

示例脚本（demo.sh）：

#!/bin/bash
set -x
name="World"
echo "Hello, $name"

运行输出：

+ name=World
+ echo 'Hello, World'
Hello, World

12. 修改 flaky test 脚本以从命令行参数接收测试命令

使用 "$@" 接收从命令行传入的完整测试命令及其所有参数（不要用 $1，因为测试命令如 cargo test my_test 通常包含多个以空格分隔的参数；用 "$@" 才能完整保留各个参数边界）：

#!/bin/bash
set -euo pipefail

if [ "$#" -eq 0 ]; then
    echo "Usage: $0 <test-command> [args...]"
    exit 1
fi

# Start CPU stress in background
stress --cpu 8 &
STRESS_PID=$!

# Setup log file
LOGFILE="test_runs_$(date +%s).log"
echo "Logging to $LOGFILE"

# Run tests until one fails
RUN=1
while "$@" > "$LOGFILE" 2>&1; do
    echo "Run $RUN passed"
    ((RUN++))
done

# Cleanup and report
kill "$STRESS_PID"
echo "Test failed on run $RUN"
echo "Last 20 lines of output:"
tail -n 20 "$LOGFILE"
echo "Full log: $LOGFILE"

运行示例：./flaky.sh cargo test my_test

13. 统计 home 目录中最常见的 5 种文件扩展名

find "$HOME" -type f 2>/dev/null \
  | awk -F/ '{print $NF}' \
  | awk -F. 'NF>1 && $1!="" {print $NF}' \
  | sort \
  | uniq -c \
  | sort -nr \
  | head -n 5

逐段解析：

  1. find "$HOME" -type f 2>/dev/null：递归找出 $HOME 下所有普通文件，忽略无权限访问目录的报错。
  2. awk -F/ '{print $NF}'：只取路径最后一部分（纯文件名），避免目录名里带 .（如 .config/）造成干扰。
  3. awk -F. 'NF>1 && $1!="" {print $NF}'：按 . 分隔，只保留有扩展名且不是纯隐藏配置文件（如 .bashrc）的文件，输出最后一个字段（扩展名）。
  4. sort | uniq -c | sort -nr | head -n 5：排序 → 合并去重并计数 → 按次数从大到小数值排序 → 取前 5 名。

14. find + xargs 统计所有 .sh 文件行数（含空格处理）

加分项版本（安全处理含空格或特殊字符的文件名）：

find . -type f -name '*.sh' -print0 | xargs -0 wc -l

原理：find 的 -print0 会用空字符 NUL（\0）而非换行符分隔每个路径；xargs -0 则以 \0 为分隔符解析输入，因此文件名中的空格不会导致参数被错误拆开。两者必须成对使用——只改一边，空格文件名仍会被拆开。

18. 拆解 SSH 日志处理管道 & 统计最常使用的 Shell 命令

第一部分：SSH 日志处理管道拆解

  1. ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' 通过 SSH 登录远程主机 myserver，查看上次启动期间（-b-1）sshd 服务的日志，筛选出包含 "Disconnected from" 的行。
  2. | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' 开启扩展正则表达式（-E），匹配断开连接日志的整行内容，使用捕获组 (.*) 提取出 user 之后、IP 地址（[^ ]+ 表示一段非空格字符）之前的用户名，并将整行替换为该用户名 \1。
  3. | sort | uniq -c 先按字典序排序（使相同的用户名连续排列，这是 uniq 正常去重的前提），再用 uniq -c 合并连续重复的用户名，并在每行前加上出现次数。
  4. | sort -nk1,1 | tail -n10 按第 1 列（-k1,1）的数值大小（-n）升序排序，然后取最后 10 行（即出现次数最多的前 10 个用户名）。
  5. | awk '{print $2}' | paste -sd, 用 awk 只提取第 2 列（去掉前面的计数，只保留用户名），最后用 paste -sd, 将多行合并为一行，并以逗号 , 分隔输出。

第二部分：统计 ~/.bash_history 最常用的 Shell 命令

  • Bash（~/.bash_history）：

    awk '{print $1}' ~/.bash_history | sort | uniq -c | sort -nr | head -n 10

  • ZSH（若 ~/.zsh_history 开启了带时间戳的扩展历史格式，如 : 1700000000:0;git status）：

    sed -E 's/^: [0-9]+:[0-9]+;//' ~/.zsh_history \
  | awk '{print $1}' \
  | sort | uniq -c | sort -nr | head -n 10
